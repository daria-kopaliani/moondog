Illustrative example. This fictional report explains the format. It is not evidence of client work or an actual test run.

Example app: Sample Export Utility
Problem: A successful purchase does not unlock export.
Scope: One purchase flow. No subscription server or backend.

1. Finding

The example purchase completes, but the export screen keeps its previous access state. Restarting the example app refreshes that state.

Release recommendation: Hold the affected purchase flow until purchase and restore checks pass.

2. Reproduction

  1. Open a fresh installation without an existing purchase.
  2. Open the export screen.
  3. Buy the one-time unlock with a sandbox account.
  4. Wait for the purchase confirmation.
  5. Try to export without restarting the app.

Expected: Export becomes available after verified purchase.
Observed in this example: The screen still asks for payment.

3. Evidence register

ItemWhat a real report records
BuildRepository commit, version, build number, and bundle ID
EnvironmentDevice, OS, Xcode, and purchase test environment
RecordingRedacted screen recording with reproduction timestamps
LogsRelevant transaction and access-state events without secrets
CodeFile and line references supporting the cause

4. Cause and uncertainty

In this example, the screen reads a cached value instead of observing the shared access state.

A real report separates confirmed causes from hypotheses. It records any unavailable device, account, build, or configuration.

This example does not verify production purchases, server notifications, refunds, or App Review outcomes.

5. Proposed repair

Update the example screen to observe the shared access state. Confirm that purchase and restore both update this state.

Example quote: USD 750 for one agreed cause, including checks and handoff. The USD 250 diagnosis remains a separate charge.

The real quote names files or components, excluded work, acceptance checks, and delivery dates before any repair starts.

6. Acceptance checks

ScenarioPass condition
Successful purchaseVerified purchase unlocks export without restart.
Cancelled purchaseNo charge confirmation or false access appears.
Pending purchaseThe app shows a pending state and remains usable.
RestoreAn eligible existing purchase restores access.
No purchase to restoreThe app explains the result without claiming success.
RelaunchVerified access remains available.
Network interruptionThe app provides an honest error and retry route.

7. Handoff

  • Patch or pull request with the exact tested commit
  • Test results with evidence and limits
  • Build and review notes for the client
  • Instructions for rollback and removal of temporary access

Apple controls review decisions and timing. The client controls merging, signing, submission, and release.

Reference: Apple App Review Guidelines. Read on November 1, 2026.
